# 恋聊 · 恋爱聊天辅助

**先了解你和对方，再给出适合你说出口的回复。**

恋聊（Dating Chat Assistant）是一份用于 AI 助手的聊天辅助 Skill。它通过逐步问答，了解你的真实情况、聊天对象的公开信息、交往目的和表达风格，再结合实际聊天记录，提供可以直接复制的回复建议。

它适合“不知道怎么接话”“想继续聊但怕尴尬”“不想回复得像 AI”“希望表达更符合自己性格”等场景。

> **当前形态：**本仓库提供 Skill 指令文件，不是独立运行的手机 App 或网页服务。需要将 [SKILL.md](./SKILL.md) 加载到能够遵循指令的 AI 助手中使用。截图能否识别、上下文能保留多久，由所使用的平台和模型决定。

## 主要功能

| 功能 | 具体做什么 |
| --- | --- |
| 引导式问答 | 逐步了解背景，避免一开始就要求填写一整张表 |
| 本人画像 | 根据你的性格、职业、城市等信息，让建议更贴近本人 |
| 对象画像 | 根据对方公开标签、自我介绍、动态概述和聊天内容整理线索 |
| 区分事实与推测 | 分开记录已确认事实、合理推测和待验证事项 |
| 明确交往目的 | 区分约会、长期恋爱、结婚或扩大社交圈等目标 |
| 聊天风格设定 | 根据本人性格调整语气，也支持明确指定的特殊风格 |
| 三档回复建议 | 提供直接回应、回应后引导、反问引导三种思路 |
| 随对话更新 | 收到新回复后，先修正画像，再生成下一轮建议 |
| 手机端复制 | 回复正文单独引用，每条一般 1–3 句，附一句简短说明 |

## 适合哪些场景

- **刚认识，不知道怎么开口：**从公开资料中寻找合适的切入点。
- **对方回了一句话，不知道怎么接：**结合上下文给出不同接法。
- **聊天总是一问一答：**尝试从回应自然过渡到可以继续讨论的话题。
- **想认真发展关系：**让表达方式与长期交往目的保持一致。
- **担心话术不像自己：**优先采用符合本人性格、见面后也能延续的表达。
- **想结束或放缓交流：**使用简洁回应，减少不必要的话题延伸。

这些是使用场景，不能据此保证对方回复、喜欢你或接受邀约。

## 快速开始

### 方法一：在 AI 对话中加载指令

这是最直接的使用方式：

1. 打开本仓库的 [SKILL.md](./SKILL.md)。
2. 复制完整内容，放入 AI 助手的自定义指令、项目指令，或新对话的首条消息中。

4. 根据助手的提问逐步回答，再提供实际聊天内容。

## 完整使用流程

### 0. 先了解你本人

助手先逐步了解你的基本情况：

- 性格：内向、外向、慢热、自来熟等。
- 工作与职业。
- 收入区间：只需要区间，不要求具体数字。
- 所在城市。
- 年龄。

**所有信息都可以选择不提供。**缺少的内容按通用表达处理，不会要求你编造身份。

这些信息主要用于调整语气、消费话题和约会安排的分寸。收入、年龄等信息默认不会直接写进发给对方的回复里。

### 1. 再了解聊天对象

可以提供以下任意材料：

- 对方社交资料中的公开标签。
- 对方的自我介绍。
- 对方公开动态或朋友圈内容的概述。
- 对方在聊天中明确说过的信息。

助手会把信息分成三类：

| 类别 | 含义 | 示例 |
| --- | --- | --- |
| 已确认事实 | 对方明确表达，或材料中能够直接确认的内容 | 对方说“我周末经常去爬山” |
| 合理推测 | 根据有限信息提出的可能解释 | 可能对户外活动感兴趣，仍需后续确认 |
| 待验证事项 | 目前没有足够依据判断的内容 | 是否喜欢两个人爬山、是否愿意接受邀约 |

**喜欢发露营照片，不等于性格外向；回复慢，也不等于没有兴趣。**标签和动态只能提供线索，不能当作心理结论。

### 2. 明确交往目的

告诉助手你希望这段交流朝哪个方向发展，例如：

- 先认识，扩大社交圈。
- 尝试约会。
- 建立长期恋爱关系。
- 以结婚为目标认真了解。

目的不同，建议的推进速度和表达分寸也会不同。

### 3. 确定表达风格

默认采用贴近本人性格的表达方式，例如：

- 幽默风趣。
- 温柔体贴。
- 真诚直接。
- 克制、慢热。
- 轻松自然。

你也可以明确要求临时尝试其他风格。若与真实本人差距较大，助手会提醒线下相处可能出现落差。

这里的人设主要用于调整表达，不应成为虚构职业、收入或经历的理由。

### 4. 进入实际聊天

提供最近几轮聊天，标清“我”和“对方”。

助手会先根据新消息更新判断，再给出回复建议。默认三种模式各给一条；如果只想要某一档，可以直接说明。

## 三种回复模式

| 模式 | 表达方式 | 适合什么时候 | 注意事项 |
| --- | --- | --- | --- |
| ① 直接回应 | 回答对方，不主动追加问题 | 想放缓节奏，或暂时结束话题 | 可能让这轮聊天自然结束 |
| ② 回应 + 引导 | 先接住对方的话，再自然延伸话题 | 多数日常聊天，默认主推 | 避免每次都连续提问，形成盘问感 |
| ③ 反问引导 | 不直接沿着原问题回答，用反问转向相关话题 | 气氛轻松，想试着调整话题方向 | 对方可能不接，不适合所有问题 |

第三档不是每次都更好。对方在认真询问具体事情时，直接回答通常更合适。

## 使用示例

以下内容是**说明格式的虚构示例**，不是实际用户记录，也不代表效果承诺。

### 示例一：开始使用

**你：**

> 我刚认识一个人，想认真了解，但不知道怎么聊。请先一步步问我。

**助手可能先问：**

> 先了解一下你：你平时聊天更偏内向慢热，还是比较外向、自来熟？

后续再根据回答继续了解职业、城市、对象信息和交往目的，而不是一次抛出所有问题。

### 示例二：生成三档回复

**背景：**本人慢热，希望发展长期关系；对方在聊天中明确说过喜欢看电影。

**最近对话：**

> 对方：今天终于忙完了，累得不想动。

**① 直接回应**

> 辛苦了，今晚就好好歇会儿，别再给自己安排任务了。

思路：接住疲惫的情绪，给对方休息空间。

**② 回应 + 引导**

> 那今晚就给自己放个假吧。你一般怎么放松，看部电影还是直接躺平？

思路：先回应状态，再结合已知兴趣轻轻延伸话题。

**③ 反问引导**

> 如果今晚突然多出两个小时完全不用管工作的时间，你最想拿来干什么？

思路：把话题转向对方想做的事；若对方明显想结束聊天，就不继续追问。

### 示例三：只要一种模式

> 只给我第二档，真诚一点，不要油腻，也别急着约见面。

### 示例四：纠正已有判断

> 之前猜她喜欢热闹不准确，她刚说自己更喜欢一个人待着。请更新画像，再帮我接这句话。

## 输入材料怎么准备

### 推荐提供

- 最近几轮完整对话。
- 双方认识的方式和大致熟悉程度。
- 你这次想达到的目的。
- 对方明确表达过的喜好或边界。
- 你的表达偏好，例如“不要太热情”“别用网络梗”。

### 尽量避免

- 只截取一句话，却省略前面的争执或关键背景。
- 把猜测写成对方已经确认的事实。
- 提供无关的身份证号、家庭住址、账号密码等敏感信息。
- 要求助手凭一条动态判断对方的人品、真实感情或心理状态。

### 便于复制的输入模板

下面的模板用于你想一次补充背景时；正常启动仍然可以逐步问答，**不必全部填写**。

```text
我的性格：
我的交往目的：
希望的表达风格：
我们怎么认识、认识多久：
对方明确说过的信息：
最近聊天：
我：
对方：
这次希望怎么处理：
```

如果上传截图，请先遮挡无关隐私。所用平台不支持图片时，转成文字并标清发言人。

## 画像如何更新

画像用于整理当前对话中的信息，不代表系统已经确认了对方的真实心理。

每收到新消息，按照以下顺序处理：

1. 记录新确认的信息。
2. 修正与新信息冲突的旧推测。
3. 保留尚未确认的问题。
4. 基于最新上下文生成回复。

例如，之前根据照片推测对方喜欢热闹，后来对方明确说更喜欢独处，应优先采用其明确表达，撤回原推测。

**当前仓库没有数据库或独立的长期记忆功能。**画像能否跨会话保存，取决于使用平台；开始新对话时，建议重新提供必要背景。

## 输出格式

默认输出包含：

- 三种模式各一条回复。
- 每条正文单独放在引用块中。
- 每条一般 1–3 句，口语化，便于手机复制。
- 每条附一句简短思路，说明为什么这样接。
- 语气符合本人性格与交往目的。

回复是建议稿，发送前请确认内容符合你的真实想法和事实。

## 隐私与使用边界

- 只使用你自愿提供的信息，以及对方已经公开或主动表达的信息。
- 不根据标签和动态声称“看透”对方。
- 不调查、挖掘对方未公开的隐私。
- 收入、年龄等个人信息默认不主动写入回复。
- 对方明确拒绝、希望停止交流时，应尊重其意愿。
- 本仓库没有连接社交账号、自动读取聊天记录或自动发送消息的代码。
- 你粘贴或上传的信息将由所使用的 AI 平台处理，数据留存与使用规则以该平台为准。
- 关系发展依赖双方意愿和实际相处，工具不能保证恋爱结果。

## 常见问题

### 需要自己部署服务器吗？

当前版本只是 Skill 指令，没有独立后端、数据库或需要启动的服务。通过已有 AI 助手使用时，不需要为本仓库单独部署服务器。

### 需要安装 Python、Node.js 或配置 API Key 吗？

当前仓库没有需要运行的程序，也没有定义依赖安装步骤。如果通过现有 AI 对话界面加载指令，不需要为这份 Skill 单独配置 API Key。所用工具本身的账号、模型或费用要求由该平台决定。

### 可以直接读取微信或其他社交软件吗？

不可以。当前版本没有此类连接能力，需要你手动提供聊天文字，或在支持图片输入的平台上传截图。

### 可以直接发送建议回复吗？

当前版本不会替你发送。你需要自行检查、选择并复制发送。

### 不想提供收入或年龄，能用吗？

可以。只提供你愿意分享的内容即可，缺少的信息不会被编造。

### 会不会每次都像在审问对方？

可以直接要求减少问题、使用陈述式回应，或只给第一档。引导话题应自然，不应机械地每条消息都追加提问。

### 可以只生成一条回复吗？

可以。指定模式和语气，例如：“只给第二档，一条就够，口语一点。”

### 能保证判断准确吗？

不能。对他人意图和性格的分析只能作为待验证的参考。对方明确说过的话，应优先于模型推测。

### 支持哪些 AI 平台？

普通文本使用要求平台能够接收并遵循较长指令；原生 Skill 导入则要求平台支持相应格式。截图还要求图像理解能力。本仓库尚未提供逐平台兼容性测试结果。
